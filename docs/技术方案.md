## 二、选型理由

### 为什么用 FastAPI 而非 Django？
- 本项目以**计算引擎**为核心，Web界面为辅，FastAPI更轻量
- 原生异步支持，调用领星API和数据库操作效率更高
- 自动生成 OpenAPI 文档，调试方便
- APScheduler 直接集成，无需额外部署 Celery + Redis

### 为什么用 PostgreSQL？
- 销量数据涉及大量时间范围查询、聚合计算，PostgreSQL性能优秀
- JSON字段用于存储批次规划等动态结构，无需额外NoSQL
- asyncpg是Python生态最快的异步PG驱动

### 为什么初期不用 Celery？
- ASIN数量初期可控（千级），APScheduler单进程足够
- 省去 Redis 部署运维成本
- 后期如果需要可平滑迁移到 Celery
